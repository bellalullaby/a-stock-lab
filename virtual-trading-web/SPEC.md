## 一、系统概述

### 1.1 一句话

双账户 A 股虚拟盘 Web 系统：小克按 SOP 纪律自动选股，酱酱手动挑票买入卖出，同台 PK 收益率。

### 1.2 核心玩法

| | 小克·纪律盘 | 酱酱·手动盘 |
|---|---|---|
| 选股方式 | SOP 引擎自动打分，门控规则自动决定买卖 | 浏览每日信号池，手动点击买入/卖出 |
| 初始资金 | ¥1,000,000 | ¥1,000,000 |
| 交易单位 | 每只 ¥100,000（固定仓位） | 自由决定，最低 100 股 |
| 🆕 同时持仓上限 | 5 只（max_positions=5） | 无限制 |
| 交易时间 | 收盘后自动执行 | 收盘后手动操作 |
| 纪律约束 | L1 门控禁止时绝不开仓 | 无约束，想买就买 |

### 1.3 用户场景

酱酱白天在单位搬砖 → 下午收盘后数据自动缓存 → 晚上回家打开 Web 页面 → 看今天的信号池 → 手动挑几只买入 → 第二天看收益曲线跟小克对比 😏

### 1.4 开发分期（🆕 v1.3）

小克建议分两期：

| 期次 | 交付物 | 目标 |
|------|--------|------|
| **第一期** | `data_collector.py` | 跑通 L1+L2+L3 缓存生成，先让数据就位 |
| **第二期** | `app.py` + Web 界面 | 有了真数据再搭界面，不会对着空页面调试 |

依赖关系：Web 展示依赖缓存数据，缓存数据依赖 collector。先有数据再有界面。

## 二、数据架构

### 2.1 缓存优先（不是实时拉）

```
收盘后 (15:30)
  ↓
data_collector.py   ← Web 页面大按钮 / 手动命令行触发（🆕 不用计划任务）
  ↓
data/cache/YYYY-MM-DD/
  ├── l1_index.json       # 五大指数 MA20/MA60 状态（🆕 五指数）
  ├── l2_boards.json      # 行业板块涨幅 TOP10
  ├── l2_zt_pool.json     # 涨停池全量
  ├── l2_zb_pool.json     # 炸板池
  ├── l2_rotation.json    # 轮动速度 + 板块连续性
  └── l3_stocks.json      # 涨停票 qt 实时数据（价格/PE/换手/市值等）
  ↓
Web 界面打开 → 读缓存 → 秒开
```

**数据源：**
- 指数 K 线 + 个股实时：`http://qt.gtimg.cn/q=<code>` 和 `http://web.ifzq.gtimg.cn/appstock/app/fqkline/get`
- 涨停池/炸板池：`https://push2ex.eastmoney.com/getTopicZTPool` / `getTopicZBPool`（✅ 2026-07-14 实测通过，81家涨停）
- 行业板块：`https://push2.eastmoney.com/api/qt/clist/get`
- 🆕 **微盘股/ST 板块日涨跌幅：** 东财 `push2.eastmoney.com/api/qt/stock/get`（腾讯 K 线 API 不支持 880864/880897，v1.4 降级为只用当日涨跌幅）
- 🆕 **备用数据源：** 同花顺热点 `basic.10jqka.com.cn`（免费、不封IP、能拿强势股+题材归因，缺乏封板资金精确数据）

### 2.2 为什么缓存而不是实时

1. 白天在单位不方便摸鱼，晚上操作时数据接口可能已经关了
2. 收盘快照是唯一有意义的 SOP 数据——盘中数据跟收盘信号不一致
3. 缓存文件可以直接给两个系统共用（小克 SOP 引擎 + 酱酱 Web 盘）

### 2.3 数据采集触发方式（🆕 v1.3 修改）

v1.2 写了 Windows 计划任务，但酱酱白天在单位搬砖、电脑大概率关机。改成两种手动方式：

1. Web 页面醒目大按钮「📡 拉取今日数据」
2. 命令行：`python data_collector.py --date 2026-07-20`

不做定时任务——"定时任务失败了但我不知道"的烦恼 > 自动化的便利。

### 2.4 历史数据回放

有了缓存文件，历史回放就简单了：选一个日期 → 读缓存 → 重现那天的信号池 → 酱酱可以"假装在那天做决策"。

## 三、策略规则（给 cc 参考，小克盘用）

### 3.1 L1 宏观门控

**🆕 v1.3：五指数体系**（从三指数升级，虚拟盘实盘验证有效）

| 指数 | 代码 | 作用 |
|------|------|------|
| 上证指数 | sh000001 | 主板大盘股情绪 |
| 深证成指 | sz399001 | 深市权重+科技 |
| 创业板指 | sz399006 | 成长股风险偏好 |
| 🆕 微盘股 | sz880864 | 散户/游资活跃度，底部信号 |
| 🆕 ST板块 | sz880897 | 风险偏好最低层 |

**L1 判定规则（三指数）：**

| 状态 | 条件 | 操作 |
|------|------|------|
| 多头趋势 | 3/3 指数站上 MA20+MA60 且 MA 上行 | 正常交易 |
| 震荡市 | 不满足多头也不满足系统性风险 | 降低权重 |
| 系统性风险 | ≥2/3 指数在 MA20 下方 且 MA20 下行 | **禁止开仓** |

**🆕 门控降级条件（L1 从"暂停"→"降低权重"的触发条件）：**
以下三个信号满足**两个**即可降级：

| # | 信号 | 条件 | 数据源 |
|---|------|------|--------|
| 1 | 微盘股翻红 | 微盘股当日涨跌幅 > 0% | 东财板块 `push2` 实时涨幅（🆕 v1.4：无K线→改用当日涨跌幅） |
| 2 | ST 板块翻红 | ST 板块当日涨跌幅 > 0% | 东财板块 `push2` 实时涨幅（🆕 v1.4：同上） |
| 3 | 两主板站上 MA20 | ≥2 个主板指数（上证/深证/创业板）收盘站上 MA20 | 腾讯 K 线 API（✅ 可用） |

> 🆕 **v1.4 修订说明（cc review）：** 微盘股（sz880864）和 ST 板块（sz880897）是东财概念板块指数。实测腾讯 `ifzq.gtimg.cn` 和 `qt.gtimg.cn` 均无法获取这两个代码的 K 线数据（`day` 数组始终为空），因此无法计算 MA20/MA60。降级条件从"站上 MA20 且 MA20 上行"改为只用当日涨跌幅 > 0%。本质没变——微盘和 ST 代表市场最敏感的两层资金，翻红本身就是底部信号。灵敏度略高于 MA 交叉版本（更易触发降级），方向正确。

**🆕 量价配合分析（虚拟盘 v1.3 新增维度）：**
L1 不仅要看价格 vs MA，还要看成交量配合：
- 价跌量缩（量比 < 0.9）→ 缩量阴跌，底部蓄力，不是恐慌
- 价跌量增（量比 > 1.2）→ 恐慌抛售，真正的系统性风险
- 价涨量增 → 良性反弹，有资金支持
- 价涨量缩 → 反弹虚，缺乏持续性

> ⚠️ 回测结论：L1 门控是最大的 alpha 来源，L3 裸跑 D5 +0.02%，加 L1 门控 → D5 +0.53%
>
> 🆕 **实盘验证（2026-07-14~20，5个交易日）：** L1 连续 5 天判"系统性风险"，虚拟盘空仓 ¥1,000,000。如果无视 L1 强买 10 只信号票 → 仅 5 天后 ¥865,794（-13.4%）。L1 门控领先 ¥134,206。2/10 胜率，8 只亏钱，元件板块最强信号东山精密 -16.4%、风华高科 -29.5%、宿迁联盛天地板 -34.4%。唯一赢家哈药股份 +30.1%。

### 3.2 L2 涨停池 + 题材

从东财涨停池获取全量涨停票，统计连板分布、行业集中度、炸板率。

**⚠️ 信号池必须限定为涨停池。** 这是策略的根基，不可省略：

| 池子 | 信号数(CSI 300 H1) | D5 均值 | 结论 |
|------|---------------------|---------|------|
| 全市场 | 2,597 | — | 92% 噪音，组合亏 -10% |
| 涨停池 | 215 | — | 组合 +12.43%（🆕 修正：原 v1.2 写 +22.45% 是 swing 幅度，绝对收益是 +12.43%） |

非涨停信号 D1 均值 -0.16%，没有短线优势。**不在涨停池里的票不参与 buy_score 打分。**

**🆕 涨停池 API 验证（2026-07-14 实盘拉通）：**

```python
import requests

# 涨停池
r = requests.get(
    "https://push2ex.eastmoney.com/getTopicZTPool",
    params={"ut":"7eea3edcaed734bea9cbfc24409ed989","dpt":"wz.ztzt",
            "Pageindex":"0","pagesize":"300","sort":"fbt:asc","date":"20260714"},
    headers={"Referer":"https://data.eastmoney.com/"}, timeout=10)
# → HTTP 200, 81家涨停

# 🆕 炸板池 — 格式完全相同，仅 URL 中 ZT 变 ZB
r = requests.get(
    "https://push2ex.eastmoney.com/getTopicZBPool",
    params={"ut":"7eea3edcaed734bea9cbfc24409ed989","dpt":"wz.ztzt",
            "Pageindex":"0","pagesize":"300","sort":"fbt:asc","date":"20260714"},

```

**404 常见原因：** 没带 `Referer` 头、`date` 格式用了连字符（要 `20260714` 不是 `2026-07-14`）、非交易日。

**🆕 涨停池备用方案（如果东财 push2ex 被封）：**

| 优先级 | 来源 | 优势 | 劣势 |
|--------|------|------|------|
| 1 | 东财 push2ex | 结构化数据（封板资金/连板数/炸板次数） | 有频率限制 |
| 2 | 同花顺热点 `basic.10jqka.com.cn` | 免费不封IP，有题材归因 | 无封板资金精确结构 |
| 3 | 东财 push2 板块涨停家数 | 知道"元件今天多少涨停" | 拿不到具体哪几只 |

### 3.3 L3 个股 buy_score（🆕 v1.3 修正）

每只涨停票打 4 个买入分（R1 已废弃，满分 4 分）：

| # | 规则 | 条件 | 状态 |
|---|------|------|------|
| ~~R1~~ | ~~突破 20D 高+放量~~ | ~~close > 20D_high × 1.002 且 vol ≥ 1.25×5D_avg~~ | ❌ **已废弃** |
| R2 | 重站 5 日线+放量 | 首板涨停（≥9.0%）且连板数=1 → buy_score +1 | ✅ |
| R3 | 5/10 线上方走强 | **`close > MA5 > MA10`** 且 涨幅 ≥ 0.8% → +1 | ✅ 🆕 恢复完整条件 |
| R4 | 异常放量上行 | **`vol_ratio ≥ 1.8`**（量比=当日量/5日均量）且 涨幅 > 0 → +1 | ✅ 🆕 改用量比 |
| R5 | 刷新 20D 高点 | 涨幅 ≥ 9.5%（涨停封板）→ +1 | ✅ |

**🆕 R3/R4 修正说明（cc 发现，2026-07-15）：**

- **R4 原是"换手率 > 5%"** → 改正为量比 `vol_ratio ≥ 1.8`。换手率 = 当日成交量/流通股本，量比 = 当日量/5日均量。同一只股票流通股本不变，换手率高可能只是大盘放量（不是个股异动）。量比才是"这个股票自己今天比平时猛了多少倍"的正确指标。
- **R3 原简化成"涨幅 ≥ 0.8%"** → 恢复完整条件 `close > MA5 > MA10 AND 涨幅 ≥ 0.8%`。"走强"不只看涨幅，还要确认价格在短期均线上方且均线排列正确（MA5 > MA10）。

**R1 废弃原因（2026-07-15 实盘回测验证）：**

cc 用沪深 300 跑了 2026 H1 回测，发现三个严重问题：

1. **未限制信号池**：R1 在全市场（2,597 个信号）触发率 41%（1,077 次），制造了大量 buy_score=4 的虚高信号。实际有效信号仅 215 个（涨停池精选后），砍掉 92% 的噪音。
2. **阈值设计缺陷**：`close > 20D_high × 1.002` 对沪深 300 大盘股来说几乎每天都有票创新高，但对涨停池里的票又因为 +10% 涨停本身远超过 1.002 倍而毫无意义。这条规则在**任何池子里都是废的**——要么太松（全市场），要么永远不触发（涨停池）。
3. **实际组合验证**：未修复前组合亏 -10%，修复后（去 R1 + 涨停池过滤 + -5% 止损）绝对收益 +12.43%。

修正后 buy_score 满分降为 **4**（仅 R2-R5），评分阈值：

- buy_score ≥ 3 → 「强候选」
- buy_score = 2 → 「观察」
- buy_score ≤ 1 → 不展示
- 🆕 「风控」标签 = buy_score ≥ 3 但 L1=系统性风险 或 轮动速度=0%（电风扇行情）。技术满足但全局禁止开仓。信号池中显示但不展示买入按钮。

### 3.4 卖出信号

> ❌ **sell_score 已废弃（v1.4）。** 旧版 sell_score 规则（跌幅 ≤ -1.5%/+1, ≤ -3.0%/+1, ≥ 2=卖出）已被五层止损体系（§3.6）完全替代。回测结论：sell_score 短期幅度太小（D1 -0.05%），宿迁联盛天地板当天才触发到 2，执行时已吃满 -10%。**Web 系统不实现 sell_score 任何逻辑。** 卖出统一走五层止损（硬止损+时间+板块+炸板+连板梯度）。

### 3.5 量化轮动防御（L2 增强）

量化资金改变了板块轮动节奏——同日最强板块次日可能直接换人，追涨停就是接盘。在 L2 涨停池分析中增加三个维度：

**3.5.1 板块连续性（Sector Continuity）**

| 连续性 | 含义 | 操作 |
|--------|------|------|
| 连续 3+ 天在 TOP3 | 真主线，资金沉淀 | 正常权重 |
| 连续 2 天在 TOP3 | 初现主线，仍需确认 | 降低权重 |
| 首日冲进 TOP3 | "一日主线"，量化一日游概率高 | 仅做 buy_score≥3 的信号 |

**实现**：`data/cache/` 里每个日期都有 `l2_boards.json`，取最近 3 个交易日的行业 TOP3 求交集。

**3.5.2 板块内部结构（Sector Internal Structure）**

| 结构类型 | 特征 | 判读 |
|----------|------|------|
| 健康 | 龙头封板 + 同板块 ≥3 只涨停 + 次日不炸 | 板块有纵深，可追 |
| 分化 | 龙头涨停但小弟冲高回落（最高+8%，收+1%） | 量化拉龙头出货，危险 |
| 散沙 | 龙头涨停但同板块无其他涨停 | 孤狼，无板块效应 |

**实现**：对涨停池按行业分组，统计每个行业涨停数 + 次日平均涨幅。龙头涨停 + 同板块涨停数 < 2 → 标记「孤狼风险」。

**3.5.3 轮动速度（Rotation Speed）**

```
轮动速度 = 今日涨停 TOP5 行业 ∩ 昨日涨停 TOP5 行业 / 5
```

| 速度 | 含义 | 策略响应 |
|------|------|----------|
| 重叠 ≥ 60% | 主线延续，正常轮动 | 正常交易 |
| 重叠 20%-40% | 加速轮动，小散先跑 | 仅 buy_score≥3 |
| 重叠 = 0% | **电风扇行情** | 全面暂停，只观察 |

**🆕 实盘验证：** 7/14（元件 11家）→ 7/15（医药 9家），重叠率 = 0%。7/15 当日元件4只首板：东山精密 +0.8%（冲高回落）、沪电股份 +0.1%（十字星）、风华高科 -8.3%（暴跌）、生益科技 +3.1%（冲高回落）——电风扇行情追涨 = 接盘。

### 3.6 止损体系（小克纪律盘 + 酱酱手动盘通用）

旧版 sell_score 缺陷已在回测中暴露：天地板当天才触发、不区分连板梯度、不管板块崩塌。新版五层止损体系：

**3.6.1 硬止损（Hard Stop）**

| 条件 | 操作 |
|------|------|
| 单日跌幅 ≥ 5% | 🚨 立即卖出，不等待收盘 |
| 累计亏损 ≥ 8%（持仓期间） | 卖出，清仓该票 |

**3.6.2 时间止损（Time Stop）**

| 条件 | 操作 |
|------|------|
| 买入后 3 个交易日，累计涨幅 < +2% | 卖出 |
| 买入后 5 个交易日，累计涨幅 < +5% | 卖出 |

**3.6.3 板块止损（Sector Stop）**

| 条件 | 操作 |
|------|------|
| 持仓个股所属行业当日涨幅排名掉出 TOP10 | 减半仓 |
| 持仓个股所属行业当日涨幅排名掉出 TOP20 | 全部卖出 |
| 同板块 2+ 只股票当日炸板 | 全部卖出，不犹豫 |

**🆕 实盘验证：** 风华高科 -8.3% 那天（7/15），元件板块从第一名掉出 TOP10。不是风华高科自己的问题，是元件板块整体坍塌。

**3.6.4 炸板止损（Limit-Up Break Stop）**

| 条件 | 操作 |
|------|------|
| 昨日涨停票今日盘中开板（从涨停价回落 ≥ 2%） | 🚨 立即卖出 |
| 昨日涨停票今日收盘涨幅 < +2% | 卖出（封板失败确认） |

**实现**：收盘缓存模式下只能执行第二条（收盘涨幅 < +2%）。Web 系统可以加「次日开盘提醒」——昨天持仓中的涨停票，今天打开页面时高亮标记。

**3.6.5 连板梯度止损（Board-Gradient Stop）**

| 连板数 | 硬止损阈值 | 说明 |
|--------|-----------|------|
| 1 板（首板） | -3% | 首板最脆弱，承接不足就跑 |
| 2 板 | -5% | 有资金基础，可放宽 |
| 3 板 | -7% | 龙头级别，波动大 |
| 4 板及以上 | -8% | 妖股级别，但需配合炸板止损 |

**3.6.6 止损触发后的冷却期**

止损卖出某只票后，3 个交易日内不得重新买入同一只票。

**3.6.7 Web 界面实现**

酱酱手动盘：持仓列表每只票显示止损状态（🟢安全 / 🟡时间止损倒计时 / 🟠板块预警 / 🔴硬止损触发），触发 → 页面顶部弹红色横幅。

### 5.2 酱酱账户存储：JSON → SQLite（🆕 v1.3 修改）

v1.2 设计用 JSON，小克建议改成 SQLite。理由：

- JSON 的 `daily_log` 数组越积越多后遍历效率差
- "我历史上买过几次哈药？" → SQL 一句 `SELECT COUNT(*) FROM trades WHERE code='sh600664'`
- "这个月胜率多少？" → SQL 一句 `SELECT ... GROUP BY strftime('%Y-%m', date)`
- 持仓、交易记录、每日快照可以分三张表，结构清晰

**表设计：**

```sql
CREATE TABLE holdings (
    code TEXT, name TEXT, shares INTEGER, cost_price REAL,
    buy_date TEXT, PRIMARY KEY (code)
);
CREATE TABLE trades (
    id INTEGER PRIMARY KEY, date TEXT, type TEXT, code TEXT,
    name TEXT, price REAL, shares INTEGER, amount REAL, note TEXT
);
CREATE TABLE daily_snapshots (
    date TEXT PRIMARY KEY, total_value REAL, cash REAL,
    holdings_value REAL, pnl REAL, pnl_pct REAL
);
```

小克的 `portfolio.json` 保持 JSON 不动（SOP 定时任务继续写入），Web 系统只读它。

## 七、数据采集脚本 (data_collector.py)

### 7.1 输入

`python data_collector.py --date 2026-07-20`

### 7.2 流程

0. 🆕 **交易日检测** → 拉涨停池 → 如果返回 0 条 → 检查是否周六日/节假日 → 退出并提示"今天没有交易数据哦"
1. 拉取**三指数** K 线（腾讯 `ifzq.gtimg.cn`）→ 算 MA20/MA60 + 量比 MA20 → 判断 L1 状态 → 写 `l1_index.json`
2. 🆕 拉取**微盘股 + ST 板块**当日涨跌幅（东财 `push2` 板块接口，无 K 线）→ 计算门控降级信号 → 合并写入 `l1_index.json`
3. 拉取行业板块涨幅 TOP 10 → 写 `l2_boards.json`
4. 拉取涨停池 + 炸板池 → 写 `l2_zt_pool.json` + `l2_zb_pool.json`
5. 🆕 计算轮动速度 + 板块连续性 → 写 `l2_rotation.json`
6. 遍历涨停池 TOP 30 → 逐只调 `qt.gtimg.cn` → 写 `l3_stocks.json`
7. 调 SOP 打分逻辑（R2-R5）→ 生成信号标签（强候选/观察/风控）→ 合并写入

### 7.3 🆕 评分实现要点

- **R4 用量比 `vol_ratio`**（当日量/5日均量 ≥ 1.8），不是换手率
- **R3 完整条件**：`close > MA5 > MA10` AND `涨幅 ≥ 0.8%`
- **PE 为负**是正常的（亏损公司），标灰不拦截
- **涨停池 date 参数**：`20260720`（无连字符）
- **东财接口限流**：连续请求间隔 ≥ 1.5s，`time.sleep(1.5)`
- **涨停池 API 必须带 `Referer: https://data.eastmoney.com/` 头**
